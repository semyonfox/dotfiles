# Academic module choice and head-start planning

Use when Semyon asks which university modules to choose or wants to prepare early for a compressed semester.

## Source hierarchy

1. Treat the current official programme curriculum as authoritative for required/optional status, credits, and semester placement.
2. Expand dynamic curriculum accordions in the browser when static extraction omits module lists. If the visible accordion text hides its body, inspect the accordion container's `textContent` to recover module codes, titles, credits, and semesters.
3. Treat programme pages as current-but-qualified when they explicitly warn that offerings may change. Verify again near registration.
4. Search Semyon's Obsidian vault for prior-student notes, especially read-only reference areas such as `eidhne/`. Never edit read-only reference material.

## Analysis workflow

1. Reconstruct the credit arithmetic:
   - required credits;
   - optional credits and number of choices;
   - credits concentrated in each teaching semester;
   - placement or project timing that explains compression.
2. Separate the decision into:
   - academic/technical payoff;
   - likely assessment and workload risk;
   - overlap with Semyon's existing projects and strengths;
   - coverage available in prior notes;
   - value for interviews, placement, and later modules.
3. Count and inspect prior notes module-by-module. File count is only a coverage signal, not evidence that the notes are complete or current.
4. Read representative notes and list concrete topics rather than recommending from module titles alone.
5. Before finalising a choice, retrieve current assessment breakdowns, prerequisites, timetable clashes, lecturer/module changes, and whether options actually run that year.

## Recommendation format

- Start with the exact year structure and credit arithmetic.
- Give a ranked recommendation with a blunt reason for each option.
- Clearly label a choice as provisional when assessment details are missing.
- Distinguish a module that is enjoyable from one that is strategically safe in a compressed semester.
- Identify one option to lock early only when evidence is strong; otherwise state what evidence would change the ranking.

## Head-start design

A strong head start is not generic summer revision. Build a module map from official outcomes and prior notes, then prioritise:

1. prerequisite repair;
2. vocabulary and conceptual orientation;
3. runnable exercises for programming/systems modules;
4. assessment-shaped practice once current briefs or past papers are available;
5. a weekly workload system that protects assignment time during the compressed semester.

Do not blindly import or rewrite another student's vault. Use it as a map and reference source, then create Semyon's own notes under the canonical university metadata standard.

## Pitfalls

- Recommending options from résumé value alone.
- Treating note quantity as module ease or guaranteed grade.
- Ignoring that project-heavy options can expand to consume unlimited polishing time.
- Calling a module “safe” without checking its current assessment structure.
- Assuming a historical module offering, title, or lecturer is unchanged.
- Missing that placement can move most nominal yearly credits into one teaching semester.
