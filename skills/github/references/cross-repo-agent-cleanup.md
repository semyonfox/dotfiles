# Cross-repo repo-agent cleanup and triage

Use when a repo-agent sweep has opened or closed PRs across multiple repositories and the user asks what remains.

## Workflow

1. **Separate active PR review from local hygiene.** A repo can have no open PRs but still have stale worktrees, dirty local work, or remote branches from closed PRs.
2. **Check all PRs, not just the current base.** Use `gh pr list --state open --json number,title,baseRefName,headRefName,isDraft,mergeStateStatus,url --limit 100` for each scan-list repo.
3. **Classify each repo before acting:**
   - clean and synced
   - local branch behind only
   - dirty real source/test work
   - dirty generated/cache/IDE noise
   - dirty local data/binary/content imports
   - open PRs clean/mergeable
   - open PRs stale/DIRTY/failing
4. **Clean closed/merged PR residue after verification.** If PRs were closed/merged and worktrees are clean or disposable, remove stale worktrees and delete local/remote branches.
5. **Do not blindly clean dirty data repos.** Local databases, `.idea` metadata, and large imported binaries need explicit human decision or a preservation branch.

## Safe cleanup commands

```bash
# Inspect worktrees and branch remnants
git worktree list
git branch --list 'agent/*' 'pr-*' 'i18n*' 'coderabbit*'

# Remove a stale worktree after status has been checked
git worktree remove --force /path/to/worktree

# Delete stale local/remote branches after PR is closed/merged/superseded
git branch -D branch-name
git push origin --delete branch-name

git fetch --prune origin
```

## Semyon-facing reporting

Keep it compact. For each repo, report:

- PR queue count and highest-risk PRs
- local dirty blockers
- whether agent mutation is safe now
- one next approval item, not a stack of approvals

Dirty local source work should normally be preserved on a `wip/...` branch before agent mutation. Dirty databases, IDE files, generated bytecode, and large PDF/content imports should be explicitly called out and not committed by default.
