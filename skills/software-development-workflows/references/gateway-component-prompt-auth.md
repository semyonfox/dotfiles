# Gateway component prompt authorization

When fixing messaging-gateway interactive prompts (Discord buttons, Telegram callbacks, Slack actions, etc.), treat component clicks as a separate external surface from normal messages and slash commands.

## Pitfall

A prompt may be generated by an already-authorized user message, but the later button click often does **not** flow back through the same message/slash authorization path. If the component view is built only from static allowlists (`DISCORD_ALLOWED_USERS`, roles, global allowlists), a channel-scoped deployment can reject the very user who triggered the prompt.

Concrete pattern from Discord clarify prompts:

- Gateway worker creates a clarify prompt during an active run.
- Discord adapter sends a `ClarifyChoiceView` with buttons.
- Button callback runs `_component_check_auth(...)`, not `on_message` / slash authorization.
- If deployment is channel-scoped and has no explicit user allowlist, the user sees: `You're not authorized to answer this prompt~`.

## Durable fix pattern

1. At prompt creation time, carry the triggering principal through prompt metadata, e.g. `requester_user_id = source.user_id`.
2. At component construction time, merge that requester into the component allowlist for that one prompt.
3. Preserve existing role/user/global allowlist semantics.
4. Keep rejecting unrelated users who can see the component.
5. Add a regression test that asserts:
   - requester can answer the generated prompt;
   - unrelated user cannot answer;
   - existing thread metadata still routes to the thread/channel intended.

For Discord clarify prompts, the implementation shape was:

```python
# gateway/run.py clarify callback
clarify_metadata = dict(status_thread_metadata or {})
if source.user_id:
    clarify_metadata["requester_user_id"] = str(source.user_id)

await adapter.send_clarify(..., metadata=clarify_metadata or None)
```

```python
# Discord adapter send_clarify
component_allowed_users = set(self._allowed_user_ids or set())
requester_user_id = str(metadata.get("requester_user_id") or "").strip()
if requester_user_id:
    component_allowed_users.add(_clean_discord_id(requester_user_id))

view = ClarifyChoiceView(..., allowed_user_ids=component_allowed_users)
```

## Verification

Run the platform-specific component auth tests plus prompt rendering/resolution tests. For Discord:

```bash
python -m pytest tests/gateway/test_discord_clarify_buttons.py tests/gateway/test_discord_component_auth.py -q -o 'addopts='
```

If async tests are not collected correctly, install the repo's dev test dependency (`pytest-asyncio` as specified in `pyproject.toml`) rather than rewriting async tests around the missing plugin.
